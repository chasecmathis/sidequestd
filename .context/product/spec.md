# Product specification (SPEC)

This is the product source of truth. It replaces the former root `SPEC.md`, and
its **section numbers are unchanged**: a code comment citing `SPEC §6.3` means
[§6.3](#63-reviews-core-content) below.

The requirements are written as product intent. Where the code deliberately
differs, an **As built** note says so and links to the domain file that owns
the detail. Overall progress is tracked in the [roadmap](roadmap.md).

**Confirmed product decisions:**
- **Platforms:** A mobile app (iOS + Android) and a responsive web app, served by one shared backend API.
- **Media:** Reviews support attached **photos and short video clips** (true visual feed).
- **Gamification:** **Light** — profile stats only (games played, average rating, review count, etc.), no competitive leaderboards.
- **Included features beyond the core:** Notifications, multi-list game backlog (To Be Played / Playing / Completed / Dropped), and trending games + friend-activity feed.

## §1 Vision & Summary

Sidequestd is a social network centered on video games. Users write **reviews** (a rating + text + optional photos/clips) of games they've played, share them to a **feed** for people who follow them, discover new and trending games, track games they want to play in **backlog lists**, and interact through likes and comments. Accounts can be public or private, mirroring the privacy model of Instagram.

**Elevator pitch:** *"Letterboxd for video games with an Instagram-style social feed."*

**Primary goals:**
- Make it effortless and rewarding to log and review the games you play.
- Surface great reviews from people you follow and games you're likely to enjoy.
- Foster social interaction (follows, likes, comments) around gaming.

## §2 Target Platforms & Tech Assumptions

- **Backend:** Single REST API service; PostgreSQL primary datastore; object storage (S3-compatible) for media; background work for media processing, notifications, and trending computation.
- **Web client:** Responsive web app.
- **Mobile client:** Cross-platform for iOS + Android.
- **Auth:** Token-based (JWT access + refresh tokens). OAuth social login optional (post-MVP).
- **Game data:** Sourced from a third-party games database (IGDB) via an import/sync service; cached locally so the app doesn't depend on live third-party calls per request.
- **Realtime:** optional — live notifications can use polling for MVP, with a WebSocket (or equivalent) channel as a later enhancement.

> **As built:** FastAPI, Next.js and Expo; see [Stack](../architecture/stack.md).
> There is no queue. Background work runs as FastAPI background tasks and
> scheduled CLI jobs. Notifications use polling plus Expo push, with no WebSocket.

## §3 User Personas

- **The Logger** — plays a lot, wants a fast way to record and rate every game. Cares about backlog tracking and personal stats.
- **The Critic** — writes thoughtful reviews with screenshots/clips, wants an audience and engagement.
- **The Explorer** — mainly consumes; browses feeds, discovers trending games, follows friends and tastemakers.
- **The Private User** — shares only with an approved circle; needs strong privacy controls.

## §4 Glossary / Core Concepts

- **Game** — a catalog entry (title, cover art, summary, release date, genres, platforms).
- **Review** — a user's post about a game: rating (see §6.3), optional text, optional media (photos/clips), optional playtime. One review per user per game (editable).
- **Feed** — reverse-chronological + recommended stream of reviews from accounts the user follows.
- **Backlog List** — a user's collection of games in a status: *To Be Played*, *Playing*, *Completed*, *Dropped*.
- **Follow** — directed relationship. For public accounts it's instant; for private accounts it requires approval (a **follow request**).
- **Interaction** — a like or comment on a review.
- **Notification** — an alert generated by another user's action relevant to you.

## §5 Navigation & Screen Map

Mobile uses a 5-tab bottom navigation; web uses an equivalent left/top nav.

1. **Home / Feed** — reviews from people you follow (+ recommended).
2. **Discover** — recommended games, trending/hot games, browse by genre/platform.
3. **Search** (or a "＋ New Review" center action on mobile) — search games & users.
4. **Notifications** — activity relevant to the user.
5. **Profile** — your profile, stats, reviews grid, backlog lists; gateway to **Settings**.

Additional screens: Game Detail, Review Detail, User Profile (others), Create/Edit Review, Settings and sub-settings, Follow Requests, Followers/Following lists.

## §6 Functional Requirements

### §6.1 Onboarding & Authentication
- **Sign up** with username (unique, public handle), email (unique, private), and password. Optionally a display name.
- **Log in** with email/username + password; issue access + refresh tokens.
- **Log out**; **password reset** via emailed link/code.
- Username and email uniqueness validated with clear error messages.
- Passwords stored using a strong hash (argon2/bcrypt). Never returned by the API.
- Optional first-run flow: pick favorite genres and a few favorite games to seed recommendations, and suggested accounts to follow.

> **As built:** [Auth and sessions](../domains/auth-and-sessions.md). The
> optional first-run flow is not built. Recommendations cold-start from
> trending instead (see [Discovery](../domains/discovery.md)).

### §6.2 User Profiles
- Each profile has: avatar, username, display name, bio, **favorite games** (a short pinned/curated list), and profile **stats** (see §6.8).
- **Reviews grid/list** — an Instagram-style grid of the user's recent reviews (media thumbnail or game cover), tappable to the full review.
- **Followers / Following** counts and lists.
- **Privacy:** account is Public or Private (§6.7). A private account's reviews, stats, and lists are visible only to approved followers.
- Viewing **your own** profile shows edit affordances and access to backlog lists and settings.
- Viewing **someone else's** profile shows a Follow / Requested / Following button and (if permitted) their content.

> **As built:** [Profiles and privacy](../domains/profiles-and-privacy.md). There are at most 6 favorites.

### §6.3 Reviews (core content)
- **Create a review** for a game: select the game (via search), give a **rating**, optionally add **text**, **photos and/or short video clips**, and optional **playtime**.
  - *Rating scale:* **5-star with half-stars** (10 stops, 0.5–5.0) for social familiarity and fast scanning in feed grids. Stored internally as an integer to keep stats math clean and leave room for a future numeric view.
- **Media:** up to **10 items** per review; **at most one video** per review at MVP (multiple videos is a fast-follow). Video clips **≤ 60 seconds**. Size caps: **images ≤ 15 MB**, **video ≤ 100 MB**. Media is uploaded to object storage; server generates thumbnails and transcodes/validates clips asynchronously. Enforce type/size limits and content-length caps.
- **One review per user per game**, but the user can **edit** or **delete** their review. Editing updates timestamps.
- Review detail shows: author, game, rating, text, media carousel, playtime, like count, comment count, and whether the current user has liked it.
- Reviews respect author privacy in all surfaces (feed, profile, discover, search).

> **As built:** [Reviews and media](../domains/reviews-and-media.md). The rating
> is stored as 1–10, since 0 stars is not a stop. Clips are validated but **not
> transcoded** and get **no poster frame**. Only MP4 and QuickTime are accepted.
> The game a review is about cannot be edited.

### §6.4 Feed (Home tab)
- Shows reviews authored by accounts the current user **follows**, newest first, paginated (cursor-based).
- Includes a **recommended** blend: optionally interleave reviews of games the user is likely to enjoy or from suggested accounts (clearly distinguishable from pure follow feed).
- Each feed item supports inline **like** and a shortcut to **comment**; tapping opens review detail.
- Empty state (new users following no one) surfaces suggested accounts and trending reviews.
- **Unified Home:** there is **no separate Activity tab**. Lightweight activity events from people you follow ("Alex added *Elden Ring* to Playing", "Sam completed *Hades*") are blended **inline** between reviews to keep Home alive even when the follow graph is quiet. Reviews are the hero content and lead; activity events are visually lighter-weight — see §6.11.

> **As built:** [Home feed](../domains/feed.md).

### §6.5 Discover Tab
- **Recommended games** — personalized suggestions based on the user's ratings, favorite genres, and similar users (collaborative filtering + content signals). Cold-start uses onboarding genre/game picks.
- **Trending / Hot games** — games with the most recent activity (reviews, ratings, list-adds, likes) over a rolling window; computed by a background job (§6.11).
- **Browse** by genre and platform; "New releases" and "Popular all-time" sections.
- Each game card links to **Game Detail**.

> **As built:** [Discovery](../domains/discovery.md). Cold start uses trending,
> then popular all-time, because there are no onboarding picks.

### §6.6 Search
- **Game search** — by title, with cover art, release year, and platform in results. From a result, the user can: open Game Detail, **add to a backlog list**, or **start a review**.
- **User search** — by username/display name; respects privacy (private profiles appear but content is gated).
- Recent searches and trending searches optional.

> **As built:** [Discovery: search](../domains/discovery.md#search-spec-66). Recent and trending searches are not built.

### §6.7 Social Graph & Privacy
- **Follow** a user. If target is **public**, follow is immediate. If **private**, it creates a **pending follow request**.
- **Follow requests:** the recipient sees a list of pending requests and can **approve** or **decline**. Approving establishes the follow; declining removes it.
- **Unfollow** and **remove follower** supported. Optional **block** (post-MVP) hides users from each other.
- **Private account rules:** non-approved viewers cannot see the private user's reviews, media, stats, backlog lists, followers/following lists, or interact (like/comment). They can see only the profile shell (avatar, username, bio, follow button).
- Switching an account **private → public** does not auto-approve pending requests unless configured; **public → private** keeps existing followers.

> **As built:** [Social graph](../domains/social-graph.md) and
> [Profiles and privacy](../domains/profiles-and-privacy.md). Blocking is not built.

### §6.8 Profile Stats (light gamification)
- Displayed on profiles (subject to privacy): **games reviewed/played**, **average rating given**, **number of reviews**, **total tracked playtime** (if provided), **completed count**, **backlog count**, and a simple **rating distribution** chart.
- Optionally a "member since" and per-genre breakdown. **No competitive leaderboards or points** in this version.

### §6.9 Game Lists / Backlog
- Every user has four system lists: **To Be Played**, **Playing**, **Completed**, **Dropped**. A game occupies at most one status at a time; changing status moves it.
- Add to list from Search, Game Detail, or a review. Reorder / remove supported.
- Completing a game can optionally prompt the user to write a review.
- **Visibility:** lists inherit the account's privacy — visible to anyone who can see the profile (public, or approved followers of private accounts). No per-list privacy at MVP; a per-list "hide" toggle is a possible post-MVP addition if users ask for it.
- Custom user-created lists are **post-MVP**.

> **As built:** [Backlog](../domains/backlog.md).

### §6.10 Interactions (Likes & Comments)
- **Like / unlike** a review; like count and the current user's like state exposed via API.
- **Comment** on a review; support **nested replies** (one level of threading is sufficient for MVP). Comments have text (length-limited, 1–500 chars), author, timestamps, edit/delete by owner.
- View list of likers and list of comments (paginated).
- All interactions gated by author privacy.

> **As built:** [Interactions](../domains/interactions.md).

### §6.11 Trending & Activity (background-computed)
- **Trending games:** a scheduled worker aggregates recent activity (reviews, list-adds, likes, ratings) into a trending score per game over a rolling window (e.g., 7 days); exposed to the Discover tab.
- **Friend activity feed:** lightweight, privacy-respecting events from followed users — new reviews, list status changes, completions — surfaced **inline within the unified Home feed** (§6.4), not as a separate tab or view.

> **As built:** Trending is a daily scheduled CLI job with flat weights and no
> recency decay yet. Activity events come from `backlog_items`, with no events
> table. See [Discovery: trending](../domains/discovery.md#trending-spec-65-611)
> and [Home feed](../domains/feed.md).

### §6.12 Notifications
- Generate notifications for: **new follower** (or **follow request** for private accounts), **follow request approved**, **like** on your review, **comment/reply** on your review, and optionally **someone you follow reviewed a game you have in your backlog**.
- Notifications tab shows read/unread state; mark-as-read (individual + all). Unread badge count on the tab.
- Delivery: in-app always; **push notifications** on mobile. User can configure categories in Settings.

> **As built:** [Notifications and push](../domains/notifications-and-push.md).
> All seven types and Expo push are built. Per-category settings are not.

### §6.13 Settings (Instagram-style)
Grouped settings screen:
- **Account:** edit profile (avatar, display name, bio, favorite games), change username/email, change password, log out, delete account.
- **Privacy:** toggle private account, manage blocked users (post-MVP).
- **Notifications:** toggle categories (likes, comments, follows, requests, backlog activity), push on/off.
- **Preferences:** favorite genres/platforms (feeds recommendations), theme (light/dark), content/media autoplay.
- **Connections:** link a gaming platform account (Steam) for verified playtime.
- **About/Support:** terms, privacy policy, app version, help.

> **As built:** Profile editing (avatar, display name, bio, privacy,
> favorites), the theme, Steam connections
> ([Platform connections](../domains/platform-connections.md)), and the About,
> privacy and terms pages. There are no endpoints yet for changing username,
> email or password, deleting an account, notification categories or
> preferences.

## §7 Data Model

Use surrogate IDs and created/updated timestamps throughout. The schema as built
is documented table by table in [Models](../models/index.md), which supersedes
the greenfield entity list this section used to hold.

## §8 API Surface

REST, JSON, cursor pagination, bearer auth, served under `/api/v1`. The
endpoints as built are listed in each [domain file](../domains/index.md), and
the shared wire rules are in [API contract](../models/api-contract.md).

> **As built:** `DELETE /users/me` (account deletion) is not built. The
> originally sketched `GET /activity` was superseded by the unified Home feed
> (§6.4, §11).

## §9 Non-Functional Requirements

- **Privacy & security:** enforce private-account gating on **every** content-returning endpoint; authz checks server-side, never trust client. HTTPS only; hashed passwords; signed tokens with refresh + revocation; rate limiting on auth, search, and write endpoints.
- **Media safety:** validate MIME/size, strip EXIF/location by default, virus/dimension checks, async transcoding; serve via CDN with expiring URLs where appropriate.
- **Moderation (baseline):** report review/comment/user; blocklist; admin ability to remove content. (Full moderation tooling post-MVP.)
- **Performance:** feed and lists use cursor pagination; trending precomputed; N+1-free queries; media thumbnails for grids.
- **Accessibility:** WCAG-minded — alt text on media, sufficient contrast, dynamic type, screen-reader labels.
- **Observability:** structured logging, error tracking, basic analytics events (review created, follow, like).
- **Compliance:** account deletion removes/anonymizes personal data; privacy policy & ToS; age gate if required.

> **As built:** Gating goes through one expression
> ([Conventions](../architecture/conventions.md#the-privacy-gate)). Rate limits
> cover auth, password reset and search, but not general writes. Metadata is
> stripped from every upload. Moderation, transcoding, virus scanning and
> account deletion are not built. See the [roadmap](roadmap.md).

## §10 Scope: MVP vs. Later

**MVP (v1):** auth, profiles + favorites, games catalog + search, reviews with **photos** (video optional if time), feed (follow-based), likes, comments (one level), private accounts + follow requests, backlog lists, basic profile stats, notifications (in-app), discover with recommended + trending.

**Fast-follow (v1.1+):** video clips (if deferred), push notifications, activity feed, richer recommendations, half-star polish.

**Later:** blocking + full moderation, custom lists, social OAuth login, group/club features, per-list privacy toggles.

## §11 Resolved Decisions

- **Rating scale:** 5-star with half-stars (10 stops, 0.5–5.0), stored internally as an integer (1–10). See §6.3.
- **Media limits:** 10 items per review, at most one video, clips ≤ 60s, images ≤ 15 MB, video ≤ 100 MB. See §6.3.
- **Backlog visibility:** inherits account privacy; no per-list privacy at MVP. See §6.9.
- **Home layout:** one unified Home feed with activity events blended inline; no separate Activity tab. See §6.4 and §6.11.
